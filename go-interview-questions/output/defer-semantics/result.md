# defer-semantics 运行结果

**对应题目**：五、`defer`
**目的**：确认 `defer` 的参数求值时机、命名返回值能否被改写、循环内 defer 的执行时机
**运行方式**：`cd code/defer-semantics && go run .`
**原始输出**：`result.txt`（stdout）

## 关键输出

```
函数退出前 x = 100
函数退出前 y = 200
defer 闭包读到 y = 200
defer 参数打印 x = 1

普通返回值 return r -> 50
命名返回值 return 50 -> 100

循环已经跑完了，下面才轮到 defer
第 3 次迭代注册的 defer 执行
第 2 次迭代注册的 defer 执行
第 1 次迭代注册的 defer 执行
```

## 结论

`defer` 后面跟着的表达式，参数在**写这一行的时候**就固定了；包成闭包则是在执行时才读变量。这个差别在日志场景里会咬人。

返回值方面：改局部变量不影响返回值（早已复制出去），改命名返回值会真的改变结果。循环里的 `defer` 要等到函数结束才执行，顺序是后进先出。
