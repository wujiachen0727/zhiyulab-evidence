# range-var 运行结果

**对应题目**：四、`for range` 的变量
**目的**：确认 `for range` 循环变量语义变化的确切边界，以及它由什么决定
**运行方式**：分别进入三个模块执行 `go run .`
**原始输出**：`go121.txt`、`go122.txt`、`go126.txt`

三个模块的 `main.go` **内容完全相同**，唯一的差别是 `go.mod` 里的 `go` 行。

## 关键输出

| 模块 | `go` 行 | 实际工具链 | 闭包捕获 | `&i` 三次相同 | 协程读到的值 |
|------|--------|-----------|---------|:------------:|-------------|
| `range-var-go121` | `go 1.21` | go1.24.13 | `3 3 3` | true | `[3 3 3]` |
| `range-var-go122` | `go 1.22` | go1.24.13 | `1 2 3` | false | `[1 2 3]` |
| `range-var-go126` | `go 1.26` | go1.27.0 | `1 2 3` | false | `[1 2 3]` |

`defer` 读循环变量在三个模块里表现一致（均为 `3 → 2 → 1`），因为 `defer` 的参数在语句处就求值了。

## 结论

**决定语义的是模块声明的语言版本（`go.mod` 的 `go` 行），不是工具链版本。** 前两个模块用同一个 go1.24.13 工具链，输出却完全相反，这是最干净的证明。边界正好落在 `go 1.21` 与 `go 1.22` 之间。
