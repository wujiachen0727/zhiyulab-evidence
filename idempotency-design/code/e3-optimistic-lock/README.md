# E3 乐观锁防并发实验

## 运行环境

- Go 1.26.2 (darwin/arm64)
- 无外部依赖，纯标准库

## 运行方式

```bash
cd e3-optimistic-lock
go run main.go
```

## 实验设计

模拟多个并发请求同时扣款同一账户余额：

| 组 | 说明 | 预期 |
|----|------|------|
| 对照组 A | 无并发控制（read-modify-write 无版本校验，放大竞争窗口） | 后写覆盖先写，扣款丢失 |
| 实验组 B | 乐观锁（WHERE version=?，冲突重试） | 全部扣款生效 |

## 结果摘要

```
场景1（2笔200元并发扣款，余额1000）:
  对照组A: 最终余额 800 —— 丢了一笔扣款（本应 600）
  实验组B: 最终余额 600，冲突重试 1 次
场景2（10笔并发扣款，余额2000）:
  对照组A: 最终余额 1800 —— 只生效 1 笔，9 笔丢失
  实验组B: 最终余额 0，冲突重试 45 次
场景3（冲突不重试直接失败）:
  事务1 成功=true；事务2 成功=false（版本冲突，0 行更新）
```

## 结论

- 无并发控制时并发扣款大量丢失（10 笔只剩 1 笔）
- 乐观锁通过版本校验 + 冲突重试保证全部生效
- 冲突不重试时返回失败语义（0 行更新），由上层决定——不会静默丢扣款
