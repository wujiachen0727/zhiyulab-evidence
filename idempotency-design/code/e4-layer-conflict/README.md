# E4 层间冲突实验

## 运行环境

- Go 1.26.2 (darwin/arm64)
- 无外部依赖，纯标准库

## 运行方式

```bash
cd e4-layer-conflict
go run main.go
```

## 实验设计

核心假设：**"乐观锁失败后上层盲目重试会导致重复退款"**

真实支付语义：调用渠道退款成功 → 才落库更新状态。第一个请求在"调渠道后、落库前"崩溃，上层重试。

| 组 | 说明 | 预期 |
|----|------|------|
| 对照组 | 无幂等键，盲目重试 | 渠道退款调用 2 次（重复退款！） |
| 实验组 | 幂等键拦截重试 | 渠道退款只调用 1 次 |

## 结果摘要

```
对照组（无幂等键，盲目重试）: 渠道退款调用次数: 2
实验组（幂等键拦截重试）: 渠道退款调用次数: 1
```

## 结论（证伪实验通过）

- 乐观锁防"并发改同一行"，但**拦不住"先调外部渠道、后落库"的崩溃窗口**
- 该窗口只能靠幂等键（或状态机拒绝重复迁移）兜住
- 三层各管一类故障——层间配合才是完整防线
